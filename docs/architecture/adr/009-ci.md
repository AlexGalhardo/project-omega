# ADR-009 — Windows correctness CI and separate native performance evidence

Status: **Approved**, by owner blanket approval on 2026-10-24. Implementation evidence remains required; approval does not claim a tested result.

## Context

Windows is the only required shipping platform; CI must validate headless logic and client compilation without claiming GPU playtesting.

## Decision

**Recommendation / original design:** Use windows-2022 hosted correctness jobs, recorded image/tool versions, exact Rust, lockfile, fmt/Clippy, core tests, client check, content validation and cargo-deny. Pin workflow actions by reviewed commit SHA when implementation creates them. Native UI/audio/controller and benchmarks remain separate evidence. Canonical implementation details are in [architecture](../architecture.md); this ADR records rationale, not duplicate schemas.

## Alternatives

A broad platform matrix adds unsupported-port work; hosted GPU timings are not the dev-machine baseline; omitting native testing leaves game feel unverified.

## Evidence and limits

E4-15, E4-03, E4-11; DEC-002; quality gates. Sources resolve in the [ledger](../../research/sources.md#stage-4-verification). No project build or benchmark is implied by reading documentation.

## Consequences

Secrets are unnecessary for PR tests; read-only permissions and no untrusted PR code with release credentials. CI actions' SHAs are resolved at implementation, not fabricated in planning.

## Reversal cost

Low for adding jobs; platform support changes require scope approval and new release validation.
